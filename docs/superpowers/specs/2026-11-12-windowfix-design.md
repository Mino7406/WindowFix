# WindowFix 설계

작성일: 2026-11-12
상태: 초안 (사용자 승인 전)

## 1. 왜 만드는가

사용자는 듀얼 모니터를 쓰고, 서브모니터를 "늘 켜두는 창들의 자리"로 쓴다.
예: 서브모니터 왼쪽 넓은 칸에 Discord, 오른쪽 좁은 칸에 카카오톡 메인(친구 목록) 창, 아래쪽은 바탕화면 아이콘이 보이도록 비워 둠.
사용자의 친구도 같은 방식으로 유튜브(브라우저), 게임, Discord를 세 칸으로 나눠 둔다.

이 배치가 두 가지 경우에 깨진다.
- 컴퓨터를 껐다 켰을 때
- 창 테두리를 실수로 건드려 위치나 크기가 바뀌었을 때

매번 손으로 다시 맞추는 게 귀찮다. WindowFix는 이 배치를 저장해 두고, 깨지지 않게 지키고, 재부팅 후에도 되돌려 놓는다.

## 2. 목표

1. **프리셋**: 현재 창 배치를 프리셋으로 저장하고, 이름을 붙이고, 불러와서 적용할 수 있다. 프리셋은 여러 개 만들 수 있다.
2. **잠금**: 잠금을 켜면, 프리셋에 들어 있는 창의 위치나 크기가 바뀌었을 때 저장된 자리로 되돌린다.
3. **재부팅 후 유지**: 윈도우 시작 시 지정된 프리셋을 자동으로 적용한다.
4. **아무 프로그램이나**: Discord나 카카오톡만이 아니라 어떤 프로그램의 창이든 프리셋에 넣을 수 있다. 창 개수에도 제한이 없다.
5. **친구에게 줄 수 있음**: .NET을 따로 설치하지 않아도 실행 파일 하나로 돌아간다. (제 판단: 친구도 쓰는 상황을 고려)

## 3. 하지 않는 것 (Non-goals)

- 전체화면(독점 전체화면) 게임 창 다루기. 창 모드나 테두리 없는 창 모드 게임만 다룬다.
- 가상 데스크톱 간 배치
- 클라우드 동기화나 계정
- macOS, Linux 지원
- 창을 격자에 스냅하는 FancyZones 같은 배치 편집기. 배치는 사용자가 손으로 맞춘 걸 저장하는 방식이 기본이다.

## 4. 이렇게 되면 실패 (Anti-goals)

- **잠금이 꺼져 있는데도 뒤에서 상주하는 것.** 사용자는 트레이에 늘 떠 있는 앱을 원하지 않는다. 백그라운드 실행은 잠금이 켜져 있을 때만 한다.
- 창 스타일을 바꾸는 방식으로 잠금을 구현해서 Discord나 카카오톡 화면이 깨지거나 오작동하는 것. 예: 크기 조절 테두리(WS_THICKFRAME)를 떼어 내는 방식.
- 대상 앱과 위치를 놓고 끝없이 싸우면서 CPU를 잡아먹거나 창이 깜빡이는 것.
- 관리자 권한을 요구하는 것.

## 5. 사용자가 정한 것

### 5.1 실행 방식
- **평소에는 일반 프로그램이다.** 실행하면 메인 창이 뜨고, 닫으면 완전히 종료된다.
- **잠금이 켜져 있을 때만 백그라운드로 남는다.** 이때는 메인 창을 닫아도 프로세스가 남아 잠금을 유지한다.
- **트레이 아이콘을 표시할지 설정에서 고를 수 있다.**

### 5.2 메인 화면: B안 "모니터 미리보기형"
브라우저 시안 중 사용자가 B안을 골랐다. 시안 파일: `.superpowers/brainstorm/1632-1794493616/content/main-window.html`

- 상단: 프리셋 선택 드롭다운, [적용], [+ 지금 배치 저장]
- 가운데: 실제 모니터 배치(크기, 상대 위치)를 축소해서 그리고, 그 위에 현재 프리셋의 창들을 색깔 있는 사각형과 이름으로 표시한다.
- 창 사각형을 클릭하면 그 창의 위치와 크기(X, Y, 너비, 높이)를 숫자로 직접 고칠 수 있다.
- 하단 토글: 잠금, 트레이 아이콘 표시, 고정 버튼 표시, 윈도우 시작 시 적용

### 5.3 프리셋 저장 흐름
감지한 창을 보여 주고, 사용자가 그중에서 고르는 방식이다.
1. [+ 지금 배치 저장]을 누르면 지금 화면에 떠 있는 창을 전부 감지해 목록으로 보여 준다. 목록에는 아이콘, 프로그램 이름, 창 제목, 모니터, 크기가 나온다.
2. 모니터 미리보기에도 감지한 창들이 그려지고, 체크한 창만 진하게 표시된다.
3. 사용자가 넣을 창을 체크하고 이름을 입력하면 저장된다.

### 5.4 창마다 있는 옵션: "없으면 실행, 숨어 있으면 꺼내기"
사용자는 이 동작을 원하되, **프리셋에서 이 옵션을 켜 둔 창에만** 적용되길 원한다.
- 프로그램이 실행 중이 아니면 실행한다.
- 실행 중인데 창이 트레이에 숨어 있거나 최소화돼 있으면 꺼내서 배치한다.
- 이 동작은 재부팅 후 자동 적용될 때와 [적용]을 수동으로 누를 때 모두 해당된다.

### 5.5 떠 있는 고정 버튼
- 잠금이 켜져 있는 동안 화면 위에 작은 반투명 버튼을 띄운다. PiP처럼 다른 창 위에 떠 있다.
- 설정에서 이 버튼을 켜고 끌 수 있다.
- 버튼을 누르면 **고정 해제**, 한 번 더 누르면 **다시 고정**된다.
- 다시 고정하면 **창들이 프리셋에 저장된 원래 자리로 돌아간다.** 해제돼 있는 동안 옮긴 위치는 프리셋에 반영하지 않는다. 배치 자체를 바꾸고 싶으면 "지금 배치 저장"을 쓴다.

### 5.6 처음 쓰는 사람도 쓸 수 있는 화면 (핵심 원칙)
사용자가 구현 도중에 덧붙인 요구사항이다: **"UI를 아예 처음 쓰거나 모르는 사람도 잘 써먹을 수 있게 하는 게 핵심."**
친구에게 exe만 보내 줘도 설명 없이 쓸 수 있어야 한다. 이를 위해 다음을 지킨다 (구체적인 모습은 내 판단):
- 프리셋이 하나도 없을 때는 미리보기 자리에 "① 창을 원하는 자리에 놓기 → ② 지금 배치 저장 → ③ 창 고정 켜기" 3단계 안내를 크게 보여 준다.
- 버튼과 토글에는 쉬운 말을 쓰고, 마우스를 올리면 무엇을 하는지 한 문장으로 알려 주는 툴팁을 단다.
- 창 설정 패널에서 자주 안 쓰는 항목(제목 조건, 실행 경로·인자, 창 종류)은 "고급 설정" 안에 접어 둔다.
- 상태 줄은 방금 일어난 일과 다음에 할 일을 알려 준다. 예: "저장했어요! 아래 '창 고정'을 켜면 이 자리에 고정돼요."

## 6. 내가(Claude) 정한 것 — 사용자가 동의한 게 아니라 내 판단

사용자는 "일단 해보고 수정사항을 알려주겠다"고 했다. 그래서 아래는 빠르게 써 볼 수 있는 쪽으로 정했다.

### 6.1 기술
- **C# / .NET 10 (LTS) / WPF.** Win32 창 API(P/Invoke)를 쓰기 편하고, 모니터 미리보기 캔버스를 그리기 쉽다. .NET 8은 2026-11-10에 지원이 끝나서, 현재 LTS인 .NET 10을 쓴다.
- **배포**: `win-x64` 자체 포함(self-contained) 단일 파일 exe. .NET 설치가 필요 없다.
- **DPI**: 모니터별 DPI 인식 v2(Per-Monitor V2)를 켠다. 모니터마다 배율이 달라도 좌표가 틀어지지 않아야 한다. 모든 좌표는 물리 픽셀 기준으로 저장한다.
- **UI 언어**: 한국어

### 6.2 저장
- 설정과 프리셋은 `%APPDATA%\WindowFix\config.json`에 JSON으로 저장한다.
- 프리셋 하나에 들어가는 것: 이름, 창 목록, 저장 시점의 모니터 정보(장치 이름, 영역)
- 창 항목 하나에 들어가는 것
  - 매칭 조건: 실행 파일 이름, 제목 조건(선택), 창 클래스(선택)
  - 모니터 식별자(6.4 참고)
  - 사각형(모니터 기준 X, Y, 너비, 높이)
  - 창 상태(보통 또는 최대화)
  - "없으면 실행, 숨어 있으면 꺼내기" 켜짐 여부
  - 실행 경로와 인자
- 전역 설정: 잠금 켜짐 여부, 현재 프리셋, 트레이 아이콘 표시 여부, 고정 버튼 표시 여부와 위치, 시작 시 적용할 프리셋(없으면 시작 시 실행 꺼짐)

### 6.3 창 알아보기
- 기본은 **실행 파일 이름**으로 맞춘다. 예: `Discord.exe`, `KakaoTalk.exe`
- 같은 프로그램의 창이 여러 개면 **제목 조건**을 쓴다. 예: 제목에 "YouTube" 포함. 저장할 때 같은 exe의 창이 여러 개 체크되면 제목 조건을 자동으로 채워 두고, 사용자가 수정할 수 있게 한다.
- 대상은 보이고, 소유자가 없고(top-level, unowned), 도구 창이 아니고, 제목이 있는 창이다. 숨은 창은 "꺼내기"를 할 때만 찾는다.

### 6.4 적용
- `SetWindowPos`로 위치와 크기를 맞춘다. 창이 최대화나 최소화 상태면 먼저 보통 상태로 되돌린 뒤 맞춘다.
- 저장과 적용에 같은 좌표계를 써서, 저장한 그대로 다시 적용되게 한다. Windows 10/11 창의 보이지 않는 테두리 때문에 몇 픽셀씩 어긋나지 않도록 한다.
- **모니터 기준 좌표로 저장한다.** 창 위치는 그 창이 있던 모니터의 왼쪽 위를 기준으로 한 상대 좌표로 저장한다. 그래야 주 모니터를 바꾸거나 모니터 배치를 옮겨도 창이 같은 모니터의 같은 자리에 간다.
- **모니터를 알아보는 방법**: `\\.\DISPLAYn` 같은 이름은 드라이버 업데이트나 케이블 포트 변경으로 바뀔 수 있어서 쓰지 않는다. 대신 모니터 하드웨어 식별자(EDID 기반 장치 경로, `DISPLAYCONFIG` 대상 장치 경로 등)로 찾는다. 그걸로 못 찾으면 "주 모니터인지 아닌지 + 해상도"로 찾는다. 듀얼 모니터에서 서브모니터가 하나뿐인 흔한 경우를 커버하기 위해서다.
- 모니터는 찾았는데 해상도가 바뀌었으면, 같은 상대 위치를 쓰되 창이 모니터 밖으로 나가지 않게 잘라 맞춘다(clamp).
- 프리셋의 모니터를 끝내 못 찾으면 그 창은 건너뛰고, 결과에 "건너뜀"으로 알린다.
- 관리자 권한으로 실행된 창은 옮길 수 없다. 이런 창은 건너뛰고 알린다.

### 6.5 잠금
- `SetWinEventHook`으로 대상 프로세스 창의 이동·크기 변경 이벤트를 받는다. 이 방식은 대상 앱에 DLL을 주입하지 않는다(out-of-context).
- 사용자가 테두리를 잡고 끄는 중에는 그대로 두고, 손을 뗀 순간(드래그 종료) 저장된 자리로 되돌린다. 프로그램이 스스로 크기를 바꾼 경우도 짧게 모았다가(debounce) 되돌린다.
- 최소화는 허용한다. 다시 열면 원래 자리로 돌아온다.
- **최대화와 스냅(Win+화살표, 화면 가장자리로 끌기)은 되돌린다.** 디스코드처럼 제목 표시줄을 더블클릭하면 최대화되는 경우도 실수로 배치가 깨지는 상황이기 때문이다. 단, 프리셋에 "최대화"로 저장된 창은 최대화 상태를 지킨다.
- 대상 앱이 계속 스스로 위치를 바꾸면 짧은 시간 안에 몇 번 되돌려 본 뒤 그 창은 잠시 포기한다. 창과 계속 싸우지 않기 위해서다.
- 잠금은 "현재 프리셋", 즉 마지막으로 적용한 프리셋에 걸린다. 현재 프리셋은 설정에 저장돼서 재부팅 후에도 이어진다.
- **잠금 중에 새로 뜨거나 다시 보이는 창도 제자리로 보낸다.** 예: 잠금을 켠 뒤 손으로 실행한 Discord, 트레이에서 다시 연 카카오톡, 껐다 다시 연 브라우저. 창이 생기거나 보이게 되는 이벤트를 받아 프리셋의 매칭 조건과 비교하고, 맞으면 배치한 뒤 붙잡는다. 붙잡고 있던 창이 닫히면 놓아 주고, 다음에 맞는 창이 뜨면 다시 붙잡는다. 단, 잠금 중에는 "없으면 실행, 숨어 있으면 꺼내기"를 하지 않는다. 그건 적용할 때만 한다.

### 6.5.1 떠 있는 고정 버튼 세부 (5.5의 세부 동작)
- 모양 (사용자 결정, 구현 중 변경): **모니터 가장자리에 딱 붙은 반쪽 사각형 탭.** 화면 안쪽 모서리만 둥글다. 크기는 약 22×56 DIP이고, 위·아래 가장자리에 붙으면 가로로 눕는다. 자물쇠 아이콘이 잠김/풀림 상태를 보여 준다(파랑 🔒 / 주황 🔓).
- 표시: 다른 창보다 항상 위에 있다. 평소에는 반투명(약 45%, 풀림 상태는 90%)이고, 마우스를 올리면 불투명해진다. 작업표시줄과 Alt+Tab 목록에는 나오지 않는다. 버튼 창을 누를 때 다른 창의 포커스를 빼앗지 않는다.
- 위치: 끌어서 옮길 수 있고, 놓으면 가장 가까운 작업 영역 가장자리에 다시 붙는다. 탭의 중심을 저장한다. 기본 위치는 서브모니터 오른쪽 가장자리, 아래에서 1/5 지점이다. 저장된 위치가 화면 밖이면 기본 위치로 돌아간다.
- 짧은 시간(0.4초) 안에 연속으로 눌린 클릭은 한 번으로 친다. 더블클릭해도 풀렸다가 바로 다시 고정되지 않게 하기 위해서다.
- 클릭과 끌기 구분: 조금이라도 끌었으면 클릭으로 치지 않는다.
- 이 버튼은 **잠금 설정**(켜짐/꺼짐)이 켜져 있을 때만 보인다. 일시 해제 중에도 다시 고정할 수 있어야 하므로 버튼은 계속 보인다.
- 버튼으로 하는 "해제"는 **일시 해제**다. 잠금 설정 자체는 켜진 채로 둔다. 앱을 다시 켜거나 재부팅하면 다시 고정된 상태로 시작한다.
- 메인 창의 잠금 토글과 트레이 메뉴도 일시 해제 상태를 보여 준다. 예: "잠금 켜짐 · 일시 해제 중"
- 설정 기본값: 버튼 표시 켜짐

### 6.6 백그라운드와 트레이
- 잠금이 켜진 상태에서 메인 창을 닫으면 창만 숨기고 프로세스는 남는다. 잠금이 꺼져 있으면 종료한다.
- 트레이 아이콘이 보이면 메뉴를 둔다: 열기, 프리셋 적용(하위 메뉴), 잠금 켜기/끄기, 종료.
- 트레이 메뉴의 "종료"는 지금 실행 중인 프로세스만 끝낸다. 잠금 설정은 켜진 채로 남아서, 다음에 앱을 켜거나 재부팅하면 잠금이 다시 동작한다. 잠금을 아예 끄려면 잠금 토글을 끈다.
- **한 번에 하나만 실행된다.** 이미 돌고 있을 때 exe를 다시 실행하면 새 프로세스는 기존 프로세스에 "창 열어"라는 신호만 보내고 끝난다. 트레이 아이콘을 숨겼을 때는 이게 앱으로 돌아오는 방법이다.

### 6.7 윈도우 시작 시
- 아래 둘 중 하나라도 켜져 있으면 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 `WindowFix.exe --startup`을 등록한다. 관리자 권한이 필요 없다. 둘 다 꺼지면 등록을 지운다.
  - "윈도우 시작 시 적용"
  - 잠금. 잠금은 앱이 돌고 있어야 동작하므로, 잠금을 켜 두면 재부팅 후에도 자동으로 다시 켜진다. 이것은 "잠금이 켜져 있을 때만 백그라운드" 원칙과 맞는다.
- `--startup`으로 켜지면 메인 창 없이 조용히 돈다.
  1. "시작 시 적용" 프리셋이 지정돼 있으면 그 프리셋을 읽고 현재 프리셋으로 삼는다. 지정돼 있지 않으면 저장된 현재 프리셋을 쓴다(잠금만 켜진 경우).
  2. "없으면 실행" 옵션이 켜진 창 중 실행 중이 아닌 프로그램을 실행한다.
  3. 대상 창이 뜰 때까지 기다린다. 2초마다 확인하고, 최대 3분 기다린다.
  4. 창이 뜨는 대로 배치를 적용한다.
  5. 앱들은 로딩 후 스스로 크기를 한 번 더 바꾸는 경우가 많다(특히 Discord). 그래서 모든 창이 적용되고 몇 초 뒤에 한 번 더 적용한다.
  6. 그다음 잠금이 꺼져 있으면 종료하고, 켜져 있으면 백그라운드로 남는다.

## 7. 알려진 함정 (만드는 사람이 확인할 것)

- **Discord**: Electron 앱이고, 자기 창 위치를 기억했다가 시작할 때 복원한다. 실행 파일 경로가 버전마다 바뀐다(`%LocalAppData%\Discord\app-1.0.xxxx\Discord.exe`). 실행할 때는 `Update.exe --processStart Discord.exe` 같은 고정 경로를 쓰는 게 안전하다. 실행 경로와 인자는 사용자가 고칠 수 있게 한다.
- **카카오톡**: 시작하면 보통 트레이에 숨은 채로 켜지고, 메인 창 외에 채팅방 창이나 광고 관련 창이 따로 있을 수 있다. 메인 창을 정확히 집어내는 조건(클래스 또는 제목)과, 숨은 창을 꺼내는 방법을 실제로 확인해야 한다. 꺼내는 방법의 후보는 숨은 창에 `ShowWindow`를 하는 것, 또는 exe를 한 번 더 실행해 기존 인스턴스가 창을 띄우게 하는 것이다.
- **브라우저(유튜브)**: 제목이 탭에 따라 계속 바뀐다. 잠금 중 매칭은 처음 매칭된 창 핸들(HWND)을 계속 붙잡아 쓰고, 제목 조건은 처음 찾을 때만 쓴다.

## 8. 만드는 사람에게 맡기는 것
- 프로젝트 구조, MVVM 사용 여부, 라이브러리 선택(트레이 아이콘 등)

- 오류 메시지 문구

## 9. 진행 방식
사용자는 먼저 써 보고 고칠 점을 알려 주겠다고 했다. 그래서 첫 버전은 위 기능을 빠르게 동작하게 만드는 데 집중하고, 다듬기는 사용자 피드백을 받은 뒤에 한다.
